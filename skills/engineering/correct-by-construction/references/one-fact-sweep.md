# One-fact sweep: find every fact with two owners

Load this for a sweep rather than one located bad state: "where can this
drift", "is any fact owned twice", "what else is like this bug", after a check
said green while the enforcer said red, before trusting a status surface, or
to find several places across a target where construction can replace checks.

A fact drifts when two places both claim to author it and nothing reconciles
them. The failure always has the same shape: the copy someone reads stays green
while the copy that decides goes red, and an incident finds the gap instead of
a check. The sweep finds those pairs first. Each finding is then closed by the
protocol's steps 7 and 8.

## What counts as two owners

One authored source plus any number of generated copies is one owner. Two
owners means both copies are edited by hand, or the check answers from a
different copy than the enforcer acts on. A copy nothing checks is a second
owner even when everyone intends it to follow the first.

## The sweep

Walk every category. For each hit, record the fact, both owners, and what, if
anything, reconciles them. An empty reconciler is the finding.

1. **Check versus enforcer.** Pair every pre-flight check (`--check`, lint,
   dry run, status command) with the gate that actually refuses (publish,
   deploy, install, CI). List the gate's refusal causes and match each to a
   check-side counterpart; any refusal the check is silent about is a finding.
   Prove it by enumeration, not by reading intentions.
2. **Records versus the external system.** Anywhere the code stores what it
   believes about a client, service or peer (config hashes, install logs,
   registration entries) instead of asking the system. The system's own
   listing is the owner; the record is a cache acting as an authority.
3. **Hand-kept twins.** Fakes, fixtures or mocks that reproduce by hand what a
   real component emits (wire formats, exit codes, rendered output). Golden
   files regenerated by the real component are one owner; typed-out strings
   are two.
4. **Constants across a boundary.** The same number, cadence, name or path in
   two repositories, two languages, or code plus config (a timer interval and
   the staleness math that assumes it; a cap copied from a vendor). Also the
   provenance gap: a constant copied from an external system with no note of
   which version it was measured against.
5. **Status from display text.** Health, success or classification derived by
   matching prose meant for people (`startswith`, a substring of a message). A
   copy edit flips the verdict. The fact needs a structured field produced
   where the prose is produced.
6. **Prose restating code.** Docs, READMEs, changelogs and instruction files
   carrying counts, inventories, paths or command spellings the code also
   owns. An annotated copy ("do not trust this count; run X") is managed; an
   unannotated one is a finding.
7. **Ledgers versus machine inventories.** Human-readable summaries
   duplicating rows a machine surface owns, with nothing comparing them.
8. **Derived assets kept by hand.** Sets of generated files committed directly
   (platform icon sizes, splash screens, social cards, compiled styles)
   without a generation step. The owner is one master (a vector icon, a source
   stylesheet); every derived file is build output.
9. **Types and checks beside each other.** A hand-written type beside a
   runtime schema of the same data; a carved or loosened type standing in for
   one shaped at its source (see the data-shape reference); a runtime check
   where a type could make the state unwritable.

## Ranking

Order by how soon it bites, not by drama:

- **Already bit:** the drift has produced a wrong answer. Cite it.
- **Armed:** both owners are edited on live paths; drift is one commit away.
- **Latent:** drift needs an outside change (a vendor update, a rename) to
  matter. Name the trigger.

## Repair ladder

For each finding, take the highest rung that makes the second owner
impossible:

1. **Delete an owner:** one copy goes; readers point at the survivor.
2. **Generate the copy:** the second surface becomes build output of the first,
   and the generator is itself a judge, or nothing changed.
3. **Reconciling judge:** both stay authored, but a check fails when they
   disagree, and it has been shown failing on a real disagreement.
4. **Annotated copy:** only for prose meant for people, with the annotation
   saying which owner wins and how to verify.

A repair of "be careful" is no repair.

## Report

Lead with the solution in one sentence: the single owner, the mechanism that
applies it, and the check that prevents drift, naming the concrete file,
command or gate, never a rung name. Then, in order:

1. the single owner: the file or source that authors the fact;
2. how it is applied: the command, generator or sync that writes or enforces
   the copies;
3. how drift is caught: the check or gate that fails on any difference;
4. what to delete in the same change: every redundant copy, workflow, ruleset
   or manual lane;
5. the findings table as evidence: fact, owners, reconciler (or none), rank,
   rung.

When the findings share no root cause, say so, then lead with the
highest-ranked finding's repair in the same order, followed by the rest and
the table. Never lead with the bare table.
