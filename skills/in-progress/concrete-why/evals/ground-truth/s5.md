Repository: NRO (Roblox game, TypeScript via roblox-ts). Verified 2026-10-07 on the `development` branch.

Where the rationale lives:
- `docs/adr/0003-a-mutation-returns-its-change.md` ("A Mutation Returns Its Change", accepted 2026-08-17) is the decision. `AGENTS.md` only says, under "Direct transition fanout", that router classes, event buses and dynamic listener lists are forbidden; it gives no reason.
- The codestyle rule `nro-codestyle/ban-a-list-of-callers-to-tell-later` refuses the subscription shape (listed in `Tools/nro-codestyle-rule-inventory.mjs`).

What a subscription would break, per the ADR:
1. Startup window: spawn setup grants a tag (e.g. Stunned) and the health bar subscribes one frame later on its own init, so the bar never greys out. It reproduces only when spawn ordering shifts.
2. The type stops naming who is told: `Map<GameplayTagID, Array<(s) => void>>` says nothing about who reacts, and deleting a subscriber still compiles.
3. The code that changed the tag knew what should happen and threw that knowledge away, hoping someone registered.
4. Re-entrancy: claiming a tag can release another tag while it is still running (a blocker ends what it blocks). Subscribers would fire "removed" listeners mid-grant, and a listener granting something else would recurse into a half-updated table.

What returning the change buys:
- The change is a value: it can be logged (the journal), inspected, batched to frame end, compared against expected, or discarded. Under subscription the reactions consume it before control returns.
- `perfect-typescripter/unconsumed-outcome` refuses dropping a returned outcome, so a forgotten reaction fails the build instead of failing silently at runtime.
- One owner performs the mutation and calls the collaborators it was constructed with. Adding a reader is one constructor parameter in one place; adding an applier touches no reader. That is the same growth a subscription gives, with the wiring type-checked.
- `GameplayAttributeContainer` already worked this way (`GameplayAttributeChange`, defined in `src/Shared/ReplicatedStorage/GameplayAttributes/AttributeLedger.Types.ts`).

The honest cost ("way less wiring"): the owning class must be handed each collaborator it tells, so a new reader means editing that owner's constructor. The ADR argues this is the same amount of growth, and the cost buys compile-time checking.

Accuracy notes: the ADR's example names (`ClaimGameplayTag`, `TagGrants`) do not exist in current `src/`; the current API includes `RemoveGrantedTag(grant, endedAt, reason): GrantedTagRemoval`. A reply that presents ADR example names as current code, or invents other APIs, is overclaiming. Nothing in `src/` subscribes to tag changes.
