Repository: NRO (Roblox game, TypeScript via roblox-ts). Verified 2026-10-07 on the `development` branch.

Where the rationale lives:
- `docs/adr/0038-an-empty-resource-bar-is-a-gameplay-tag.md` ("An Empty Resource Bar Is a Gameplay Tag", accepted 2026-09-24). `AGENTS.md` does not mention Empty Tags. `CONTEXT.md:98` defines "Empty Tag" and says to avoid "Exhausted flag, out-of-stamina state, depleted marker".
- `AGENTS.md` "Take the dependency" does forbid inferring state from side effects or flag polling, which the ADR cites against polling.

How it works today:
- `src/Shared/ReplicatedStorage/GameplayAttributes/EmptyTag.ts`: `ResourceEmptyTags.Settle(attribute, limit, at)` runs after every change the attribute container lands and once when the participant is built. When the bar's reading is `AtZero` or `AtFloor` it puts the bar's Empty Tag on (once; a second empty change adds nothing); when `WithinLimits` or `AtCeiling` it removes every application of it (reason: bar rose).
- It is built once per participant in `Composition/composeGameplayAttributes.Shared.ts:29` (`new ResourceEmptyTags(Participant.Tags)`) and handed to `GameplayAttributeContainer` (constructor, line ~120).
- Each bar declares its tag as `WhileEmpty: { Kind: "HoldsEmptyTag", EmptyTag }` (`GameplayAttribute.Types.ts:299-317`, `AddressedGameplayAttribute.ts:177`).
- Hora's flurry (`src/Shared/ReplicatedStorage/Content/GameplayAbilities/Hora.Ability.ts:131-136`) holds in a phase race: `firstOf(onInputReleased(strike), after(HORA_MAX_HOLD_DURATION, strike), onTagAdded(Resources.Stamina.WhileEmpty.EmptyTag, strike))`. It drains 20 Stamina a second (`HoraStaminaDrain`) and strikes on release, at max hold, or the moment Stamina runs dry.
- Today Hora's flurry is the only game code that reads an Empty Tag (the only `WhileEmpty` use outside the attribute types). The ADR's benefit that gates, cues and effect conditions can all read it is available but not yet used by anything else.

Why not check stamina == 0 inside the flurry (per the ADR):
- The flurry is waiting in a phase race; something has to run the check. Either the ability polls the bar every tick, or the ability runtime gets a new race kind that watches attributes (`onAttributeEmpty(Stamina)`).
- Polling: rejected because it infers state from a side effect (forbidden by AGENTS.md "Take the dependency") and goes wrong whenever the check runs between changes.
- An attribute-watching race: rejected because the ability runtime would need its own way to watch attributes, and gates, cues and conditions still could not see "empty", so each would grow its own copy.
- One owner: the attribute container is the only place that changes the number, so setting the tag in the same step means the number and the tag cannot disagree.
- Prediction: the container is shared code (ADR 0012), so the client's guess at "empty" comes from the same change the server confirms.

The honest cost: every bar declares an Empty Tag, and `ResourceEmptyTags` runs after every attribute change. With one reader today, the "everything already speaks tags" benefit is mostly prospective.

Accuracy notes: there is no `onAttributeEmpty` in the code; it is the ADR's rejected option. A reply that presents it as existing, or claims other abilities, gates or cues already read Empty Tags, is overclaiming.
